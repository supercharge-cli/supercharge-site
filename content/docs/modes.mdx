# Run modes

Supercharge uses one CLI for interactive work, one-shot automation, and client integrations. Choose the entry point based on who controls the session.

| Entry point | Protocol / output | Use it when |
| --- | --- | --- |
| `supercharge` | Interactive terminal UI | You are working in a terminal. |
| `supercharge -p "Task"` | One answer, then exit | A script or CI job needs a bounded prompt. |
| `supercharge agent stdio` | ACP JSON-RPC on stdin/stdout | An editor or SDK starts the local agent. |
| `supercharge agent serve` | ACP JSON-RPC over WebSocket | A client connects to your running agent. |
| `supercharge agent headless` | Outbound WebSocket relay | An agent connects to a relay you configured. |
| `supercharge agent daemon` | HTTP inbox, with ACP WebSocket fallback | An HTTP chat client talks to a separately started agent service. |

## One-shot automation

```bash
supercharge -p "Add a health check and run the tests" --output-format plain
supercharge -p "Explain src/lib.rs" --output-format json
```

Use `--output-format streaming-json` for line-delimited session updates, or `streaming-messages-json` for message-format streaming. `--max-turns`, `--tools`, and `--disallowed-tools` apply to headless one-shot runs, not the interactive terminal UI. For approval-free trusted automation, use `--yolo`; deny rules and hooks still apply. See [CLI commands](/docs/commands) and [Permissions](/docs/permissions).

## Client integrations

For a local editor:

```bash
supercharge agent stdio
supercharge acp setup --editor zed
```

For an ACP WebSocket client:

```bash
supercharge agent --always-approve serve --bind 127.0.0.1:2419 --secret YOUR_TOKEN
```

The agent's shared flags go before `stdio` or `serve`; `--bind` and `--secret` go after `serve`. The server's default bind is `127.0.0.1:2419`. See [Agent Client Protocol (ACP)](/docs/acp) for editor setup, connection URLs, session messages, authentication, permissions, live model selection, and extensions.

## HTTP inbox

```bash
supercharge agent --always-approve daemon --bind 127.0.0.1:8790 --secret YOUR_TOKEN
```

The daemon defaults to `0.0.0.0:8790` if you omit `--bind`. When its companion HTTP server is installed, it provides the `/v1/chat` inbox. Otherwise the CLI announces a fallback to ACP WebSocket on the same bind address. Check the startup message and connect with the corresponding protocol. This mode is distinct from `agent serve` and from `-p`.
